# OpenCADStudio 插件机制

本文说明当前代码里插件是怎么发现、加载、调用和改图的。权威英文设计稿仍是 [`plugin-architecture.md`](plugin-architecture.md)；进程、协议和版本策略的内部分层见 [`crates/ocs_plugin_api/ARCHITECTURE.md`](../crates/ocs_plugin_api/ARCHITECTURE.md)。版本数字以 `crates/ocs_plugin_api/src/manifest.rs` 为准：宿主主版本是 **8**，能加载的最旧主版本是 **3**。

内置功能区（Home、绘图、修改等）不是插件。它们在 `src/modules/`，跟宿主编在同一个二进制里。插件是另外装进来的动态库。

## 三层

1. **宿主**（本仓库 `src/`）。界面、文档、撤销、命令行。插件运行时在 `src/plugin/`，对当前图的具体操作在 `src/app/plugin_host.rs` 的 `HostSession`。
2. **插件进程**。一个 `cdylib`，用 `ocs_plugin_api` 编译。宿主不把这个库 `dlopen` 进自己的进程，而是再启动一份自己，带上 `--ocs-plugin-runner`，由那个子进程去加载动态库。
3. **可选的领域引擎**。纯 `std` 的计算库，不依赖界面和 `opencadcodec`。Python 插件是这一层的例子：脚本跑在插件进程里的 RustPython 里，通过 `ocs.*` 调宿主。

崩溃被隔在插件进程里。宿主这边的 `src/plugin/mod.rs` 还有一个 panic 守卫，用来接住已经回到宿主调用栈上的恐慌，并把说明排进命令行；它挡不住插件进程里的非法内存访问。

Web / wasm 构建不加载本地动态库（`src/plugin/registry.rs` 里相关路径都包在 `not(target_arch = "wasm32")` 里）。

## 包长什么样

每个插件一个目录：

```text
<插件 id>/
  plugin.toml
  <name>.dll | .so | .dylib
```

`plugin.toml` 在真正加载本地代码之前就被读走。宿主用它做清单：id、名字、版本、说明、`api_version`、功能区排序、命令前缀，以及 API v4 及以后必须写上的 `opencadcodec` 来源和 `rustc --version`。

查找顺序（`src/plugin/external.rs`）：

1. 跟可执行文件放在一起的捆绑目录（macOS 在 `Contents/Resources/plugins`，其它平台在 exe 旁边的 `plugins`）。可用 `OCS_BUNDLED_PLUGINS_DIR` 改掉。
2. 用户目录：Windows 是 `%APPDATA%\OpenCADStudio\plugins`，macOS 是 `~/Library/Application Support/OpenCADStudio/plugins`，其它是 `$XDG_CONFIG_HOME` 或 `~/.config` 下的同名路径。可用 `OCS_PLUGINS_DIR` 改掉。

同一个 id 时，用户目录里的包盖过捆绑包。市场安装（`src/plugin/marketplace.rs`）把发布包写进用户目录。卸掉只是删文件夹，当前这次启动里已经加载的进程要到下次启动才消失。

## 加载

`PluginManager` 为每个通过门槛的包做这些事：

1. 在本机套接字上听。
2. 把宿主可执行文件再拉起来，参数是 runner 模式、套接字和动态库路径。子进程和宿主因此用的是同一份 `ocs_plugin_api`。
3. Runner 用 `libloading` 打开动态库，先读 `ocs_plugin_api_version()`，再调 `ocs_plugin_register()`。这两个符号由 `export_plugin!` 生成。注册函数若恐慌，返回空指针，runner 不会跟着垮。
4. 用环境变量里的令牌做握手。API v4 及以上走多路复用帧；更早的仍受支持的版本走一来一回的请求。
5. API v5 起调用 `on_load`。
6. 再要一次 `PluginManifest`，核对版本和 ABI 元数据。对不上就关掉子进程。

三道门（`manifest.rs` 和 `version_info`）：

| 门 | 规则 |
| --- | --- |
| API 主版本 | 插件主版本在 3 和 8 之间（含）。`OCS_PLUGIN_MAX_API_VERSION` 可以把上限临时压低，不用重编宿主。 |
| `opencadcodec` 来源 | API v4 及以上必须声明，并且和宿主这次构建用的来源一致。 |
| rustc | API v4 及以上必须声明 `rustc --version`，并且和宿主完全一致。对不上就拒绝加载，而不是等到 runner 里才崩。 |

新的宿主方法加在 trait 末尾，所以旧插件的虚表前缀仍然对得上。v2 已经不再加载：它的功能区线路类型和现在的对不上，放进来会静默注册失败。

## 一条命令怎么走到插件

命令行和功能区按钮最后都进 `src/plugin/registry.rs` 的 `try_dispatch`：

1. 用当前标签页包一个 `HostSession`（实现 `HostApi`）。
2. `PluginManager::dispatch` 按命令找已加载、且没被用户关掉的插件。
3. 请求过本地套接字到 runner，runner 调用插件的 `dispatch(&mut dyn HostApi, cmd)`。
4. 插件返回 `true` 表示这个命令是它的。需要接着点选、要输入的命令，宿主把 `PluginProcessInteractiveAdapter` 设成当前交互命令。
5. 插件进程中途死了，或这次调用报错，宿主在命令行写一行，不把整个程序停掉。

功能区方面，`ribbon_modules_enabled` 先放核心模块，再把未禁用插件的 `CadModule` 按 `ribbon_order` 接上去。插件命令名也会进命令行补全，不只出现在按钮上。

`BuiltinPlugin` 四个入口：

- `manifest`：身份和 API 版本。
- `ribbon`：这个插件自己的功能区页。
- `dispatch`：执行一条命令。
- `on_load`：v5 起的加载回调，默认空。

## 插件能对图做什么

`dispatch` 拿到的是 `&mut dyn HostApi`，看不到 `OpenCADStudio` 这个具体类型。进程外插件要记住：

- `document()` / `document_mut()` 是**本地快照**。直接改快照里的旧实体不会写回宿主。
- 增、改、删要走 `add_entity`、`update_entity`、`remove_entity`，它们经 IPC 提交，并按宿主的撤销规则入栈。
- 图上的领域数据放在实体的 XDATA 里（按句柄和 APPID 读写），这样能跟着 DWG/DXF 走，不另建一份旁路数据库。
- API v8 在命名对象字典上增加了 XRecord 的按名创建、读取、更新、删除和列举。失败发生在任何改动之前，图保持原样。插件若先 `push_undo`，同一次操作里的实体写入和 XRecord 写入合成一步撤销。
- 大图读取不必把整份 `CadDocument` 从套接字克隆过去。v3/v4 由宿主发布一块共享内存快照，插件只读映射（`shm`、`host_v4`）。
- 命令行用 `push_info` / `push_output` / `push_error`。
- v6 起可以读系统变量；当前宿主实现了 `CLAYER`、`SNAPANG`，以及只读的 `CTAB`。

v4 的套接字是多路复用的：请求、响应和通知可以交错，用关联 id 配对。文档变化这类通知是尽力送达，丢了只记日志。

## 和核心模块的差别

| | 核心模块 `src/modules/` | 插件 |
| --- | --- | --- |
| 编译 | 打进宿主 | 独立 `cdylib` |
| 进程 | 宿主进程 | runner 子进程 |
| 契约 | 可以直接用宿主类型 | 只能用 `ocs_plugin_api` |
| 安装 | 发版即有 | `plugin.toml` + 动态库，可从市场装 |
| Web | 随 wasm 构建 | 不加载 |

仓库里的 `plugins/opencad-python` 是第一方 Python 包：命令 `PY_EVAL`、`PY_RUN`，脚本里直接用 `ocs` 模块。它的沙箱说明在该目录的 `PLUGIN.md`。新插件不要改宿主源码；从 `docs/plugin-template/` 的 `plugin.toml` 起一份自己的包，并用 `export_plugin!` 导出上面那两个 C 符号。
