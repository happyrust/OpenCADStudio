# 平台层需求

本文档定义 P&ID 平台的平台层需求，共 15 条，按身份与会话、角色与成员管理、项目空间、权限模型、审计日志、系统配置六个小节组织；编号规则见 `docs/pid-platform/requirements/00-overview.md`。

## 身份与会话

### REQ-PLAT-001 登录失败锁定

- **优先级**：必须
- **用户故事**：作为平台用户，我希望连续输错密码达到阈值后账号被自动锁定，以便抵御暴力破解尝试。
- **验收标准**：
  1. 同一用户连续密码错误达到 `失败次数阈值`（默认 5 次，可配置范围 1–20 次）后账号变为锁定状态，锁定 30 分钟内即使输入正确密码也返回锁定提示。
  2. 管理员为该用户重置密码后锁定立即解除，用户输入正确新密码 1 次即可登录。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 用户名 | String | 是 | — |
  | 密码 | String | 是 | — |
  | 失败次数阈值 | Integer | 是 | 默认 5，范围 1–20 |
  | 锁定时长 | Integer | 是 | 默认 30 分钟 |
- **来源**：§4.1.1

### REQ-PLAT-002 密码有效期与强制改密

- **优先级**：必须
- **用户故事**：作为系统管理员，我希望密码超过有效期后强制用户改密，以便降低长期使用同一密码的泄露风险。
- **验收标准**：
  1. `密码有效期` 默认 90 天，到期未改密的用户登录被拒绝并提示须由管理员重置，无法进入工作台。
  2. 用户在首选项凭旧密码与合规新密码（≥ 8 字符且同时含字母与数字）自助改密成功后，有效期自改密时刻重新计为 90 天。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 密码有效期 | Integer | 是 | 默认 90 天 |
  | 旧密码 | String | 是 | — |
  | 新密码 | String | 是 | ≥ 8 字符，含字母与数字 |
- **来源**：§4.1.1

### REQ-PLAT-003 邮箱验证码找回密码

- **优先级**：必须
- **用户故事**：作为平台用户，我希望通过账号绑定邮箱的验证码找回密码，以便在遗忘密码时自助恢复访问。
- **验收标准**：
  1. 验证码为 6 位数字、10 分钟内有效；同一账号 60 秒内只能请求 1 次验证码，绑定邮箱无效时不发送。
  2. 验证码最多尝试 5 次；重置成功后该账号全部旧会话立即失效，须用新密码重新登录。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 邮箱 | String | 是 | 必须为账号已绑定邮箱 |
  | 验证码 | String | 是 | 6 位数字 |
  | 新密码 | String | 是 | ≥ 8 字符，含字母与数字 |
- **来源**：§4.1.1

### REQ-PLAT-004 会话超时与并发登录

- **优先级**：必须
- **用户故事**：作为系统管理员，我希望会话在无操作超时后失效且并发会话数受限，以便控制闲置会话与账号共享风险。
- **验收标准**：
  1. 会话连续 30 分钟无操作后失效，之后任何写操作返回 `401`，客户端显示「会话已过期，请重新登录」。
  2. 同一账号最多 3 个并发会话，建立第 4 个会话时最早的 1 个会话被注销。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 会话超时 | Integer | 是 | 默认 30 分钟 |
  | 最大并发会话 | Integer | 是 | 默认 3 |
  | 会话令牌 | String | 是 | — |
- **来源**：新增设计

## 角色与成员管理

### REQ-PLAT-005 预置角色不可删除

- **优先级**：必须
- **用户故事**：作为系统管理员，我希望预置角色始终存在且不可删除，以便权限体系保有稳定的基础角色。
- **验收标准**：
  1. 对 `系统管理员`、`所有用户`、`项目管理员` 任一预置角色发起删除均返回 `PRESET_ROLE_PROTECTED`，角色列表仍显示 3 行。
  2. 权限启用或禁用变化后 `系统管理员` 在管理模式下的全部权限不受影响；被指定为 `项目管理员` 的成员不可从该角色移出。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 角色名 | String | 是 | — |
  | 角色类型 | Enum(预置/自定义) | 是 | — |
  | 成员数 | Integer | 是 | 只读 |
- **来源**：§5.1.7

### REQ-PLAT-006 自定义角色与成员继承

- **优先级**：必须
- **用户故事**：作为项目管理员，我希望按自定义角色统一授权并让成员自动继承角色权限，以便减少逐人授权的配置量。
- **验收标准**：
  1. 成员加入自定义角色后立即继承该角色全部权限项，无需逐人授权；同一用户属于多个角色时权限取并集。
  2. 角色名称在项目空间内唯一，重名保存返回 `409`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 角色名称 | String | 是 | ≤ 64 字符，项目空间内唯一 |
  | 说明 | Text | 否 | — |
  | 成员 | UserList | 是 | — |
  | 权限项 | PermissionSet | 是 | — |
- **来源**：§5.1.7.3.2

### REQ-PLAT-007 角色删除保护

- **优先级**：必须
- **用户故事**：作为系统管理员，我希望被引用的角色在删除前得到保护提示，以便不破坏在用的业务流程与权限配置。
- **验收标准**：
  1. 删除被业务流程、工作流或权限设置引用的角色返回 `ROLE_IN_USE`，提示中列出引用位置数量。
  2. `成员数` 大于 0 的角色须先指定 `成员迁移目标` 完成成员迁移；删除成功后该角色从角色列表消失，成员账号保持不变。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 角色 ID | String | 是 | — |
  | 引用计数 | Integer | 是 | 只读 |
  | 成员迁移目标 | String | 否 | 成员数大于 0 时删除前必填 |
- **来源**：§5.1.7

## 项目空间

### REQ-PLAT-008 项目空间创建与命名唯一

- **优先级**：必须
- **用户故事**：作为平台管理员，我希望项目空间名称与编号在平台内唯一，以便各模块按名称与编号准确引用同一项目。
- **验收标准**：
  1. `项目名称` 或 `项目编号` 与既有项目空间或项目模板重复时，创建返回 `409` 并在响应中指出冲突字段名。
  2. 创建时必须选定 1 套图例标准；创建成功后项目空间列表按创建时间倒序排列，最新项目显示在第 1 行。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 项目名称 | String | 是 | ≤ 64 字符 |
  | 项目编号 | String | 是 | 8–32 字符 |
  | 图例标准 | String | 是 | — |
  | 管理员 | User | 是 | — |
- **来源**：§5.1.11

### REQ-PLAT-009 项目空间状态与只读降级

- **优先级**：必须
- **用户故事**：作为项目管理员，我希望按项目空间状态控制访问与写操作，以便项目暂停或归档时防止误改动。
- **验收标准**：
  1. `项目状态` 取值为 `有效`/`无效`/`暂挂`/`仅查看`；`无效` 与 `暂挂` 状态下任何访问返回 `PROJECT_UNAVAILABLE`，`仅查看` 状态下读操作正常、一切写操作返回 `PROJECT_READ_ONLY`。
  2. `仅查看` 状态下前端隐藏新建、编辑、删除按钮，页面中这 3 类按钮可见数减少为 0。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 项目状态 | Enum(有效/无效/暂挂/仅查看) | 是 | — |
  | 状态变更人 | String | 是 | 只读 |
  | 状态变更时间 | DateTime | 是 | 只读 |
- **来源**：§5.1.11

## 权限模型

### REQ-PLAT-010 三级授权链

- **优先级**：必须
- **用户故事**：作为权限管理员，我希望授权判定沿角色权限、PBS 节点 ACL 与图纸状态三级收敛，以便把权限边界精确落到每张图纸。
- **验收标准**：
  1. 判定顺序固定为角色功能权限、沿 PBS 自根向下取最近 1 条 ACL、图纸状态共 3 级；任一级拒绝即整体拒绝，响应返回首个拒绝级别与对应错误码。
  2. 角色权限与 PBS 节点 ACL 均允许且图纸状态为 `单人编辑` 或 `协同编辑` 时写操作通过；同一图纸切为 `只读` 后同一写操作被拒绝。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 角色 | String | 是 | — |
  | PBS 节点 | String | 是 | — |
  | 图纸状态 | Enum(单人编辑/协同编辑/只读) | 是 | — |
  | 允许 | Boolean | 是 | — |
  | 拒绝 | Boolean | 是 | — |
- **来源**：新增设计

判定示例（角色权限 × PBS 节点 ACL × 图纸状态 → 判定）：

| 角色权限 | PBS 节点 ACL | 图纸状态 | 判定 |
| --- | --- | --- | --- |
| 允许 | 允许 | 单人编辑 | 允许 |
| 允许 | 允许 | 只读 | 拒绝（图纸状态） |
| 允许 | 拒绝 | 协同编辑 | 拒绝（PBS 节点 ACL） |
| 拒绝 | 允许 | 单人编辑 | 拒绝（角色权限） |

### REQ-PLAT-011 功能权限并集与菜单可见性

- **优先级**：必须
- **用户故事**：作为权限管理员，我希望菜单按用户权限并集渲染，以便用户只看到被授权的功能入口。
- **验收标准**：
  1. 用户权限为其直接权限与所属全部角色权限的并集；缺少 `查看` 权限的菜单节点不渲染，可见菜单项数量减少对应条数。
  2. 勾选任一写权限（新建/修改/删除/部署）时 `查看` 自动被勾选；取消 `查看` 时该节点全部写权限同步取消。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 菜单节点 | String | 是 | — |
  | 权限项 | Enum(查看/新建/修改/删除/部署) | 是 | — |
  | 来源 | Enum(用户/角色) | 是 | — |
- **来源**：§5.1.6.3

## 审计日志

### REQ-PLAT-012 审计日志记录字段

- **优先级**：必须
- **用户故事**：作为审计人员，我希望每次写操作都记录完整固定字段，以便事后追溯任何一次变更。
- **验收标准**：
  1. 执行 1 次写操作后审计日志新增 1 行，`操作模块`、`操作类型`、`操作时间`、`操作对象`、`用户`、`公司`、`IP`、`来源工作区`、`变更前后值` 9 个字段全部写入。
  2. 按位号检索可查到该对象最近 1 次修改记录；日志只追加不提供修改接口，修改请求返回 `405`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 操作模块 | String | 是 | — |
  | 操作类型 | String | 是 | — |
  | 操作时间 | DateTime | 是 | — |
  | 操作对象 | String | 是 | — |
  | 用户 | String | 是 | — |
  | 公司 | String | 是 | — |
  | IP | String | 是 | — |
  | 来源工作区 | String | 是 | — |
  | 变更前后值 | Text | 是 | — |
- **来源**：§5.1.13

### REQ-PLAT-013 审计日志保留与清理

- **优先级**：应该
- **用户故事**：作为系统管理员，我希望审计日志按保留策略自动清理并支持容量预警，以便日志规模长期可控。
- **验收标准**：
  1. 自动清理按 `清理频率`（每日/每周/每月）执行，`保留时长` 默认 180 天；手动清理可选「不保留」，执行后清空全部日志行。
  2. 日志容量达到 `预警阈值` N 后系统每天发送 1 次通知，直至容量低于阈值；预警方式支持内部通知与邮件多选。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 保留时长 | Integer | 是 | 默认 180 天 |
  | 清理频率 | Enum(每日/每周/每月) | 是 | — |
  | 预警阈值 | Integer | 是 | 按日志容量 N 设定 |
  | 预警方式 | MultiEnum(内部通知/邮件) | 是 | 可多选 |
- **来源**：§5.1.13.3.2.4

## 系统配置

### REQ-PLAT-014 系统运行参数

- **优先级**：必须
- **用户故事**：作为系统管理员，我希望平台运行参数集中配置并按生效时间下发，以便统一调整安全与运行策略。

  | --- | --- | --- | --- |
  | 参数键 | String | 是 | — |

  | 生效时间 | DateTime | 是 | 只读 |
- **来源**：新增设计

### REQ-PLAT-015 配置包发布与影响分析

- **优先级**：必须
- **用户故事**：作为配置管理员，我希望配置包经错误检查与影响分析后再部署，以便可控地把配置变更发布到目标环境。
- **验收标准**：
  1. 流程固定为配置项 → 配置包 → 错误检查 → 发布 → 下载 zip → 导入 → 影响分析 → 部署 8 个环节；错误级别问题全部解决后方可继续，警告可继续。
  2. 部署前影响分析展示新增、更新、删除 3 类计数；点击「下一步」后流程不可取消；导入校验失败时生成 1 个错误文件供下载。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 配置包名称 | String | 是 | — |
  | 文件名 | String | 是 | — |
  | 状态 | Enum(草稿/已发布/已导入/已部署) | 是 | — |
  | 影响计数 | Integer | 是 | 只读 |
- **来源**：§5.1.13.2.2.2.2
