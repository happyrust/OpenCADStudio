# 类型库与属性模型需求

本文档定义 P&ID 平台类型库与属性模型需求，共 15 条，按业务类型树、属性分组、数据要素与数据类型、属性级别与默认值、属性拼接、类型与符号的关系、规则继承七个小节组织；编号规则见 `docs/pid-platform/requirements/00-overview.md`。

## 业务类型树

### REQ-TYPE-001 类型树层级与类型编码唯一

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望类型编码全局唯一且创建后不可修改，以便对象类型在类型库中被稳定引用。
- **验收标准**：
  1. 新建类型点击【确定】时对 `类型编码` 做全局唯一值验证，重复返回 `409`；保存成功后类型树新增 1 个节点。
  2. 对已存在类型提交修改 `类型编码` 的请求返回 `409`，仅 `名称` 与 `描述` 可修改；类型树支持拖拽改变父子关系与同级顺序，新建子类后父节点自动展开且子节点位于末位。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 类型编码 | String | 是 | ≤ 32 字符，全局唯一，创建后只读 |
  | 名称 | String | 是 | ≤ 64 字符 |
  | 描述 | Text | 否 | — |
  | 父类型 | String | 否 | — |
- **来源**：§5.1.4.3.1.2.2.1

### REQ-TYPE-002 删除类型连带删除子节点

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望删除类型时连带删除其下全部子节点并先看到影响范围，以便删除结果可预期。
- **验收标准**：
  1. 删除含 3 个子节点的类型时，确认框显示 `受影响子节点数` 为 3，确认后该类型与 3 个子节点一次性删除。
  2. 删除操作写入审计日志并记录全部被删 `类型编码` 列表；删除后类型树节点总数减少对应数量。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 类型编码 | String | 是 | — |
  | 受影响子节点数 | Integer | 是 | 只读 |
  | 确认标志 | Boolean | 是 | — |
- **来源**：§5.1.4.3.1

## 属性分组

### REQ-TYPE-003 属性分组创建与排序

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望在类型下创建属性分组并对分组与组内属性拖拽排序，以便属性按业务语义组织呈现。
- **验收标准**：
  1. `分组名` 在同一类型内唯一，重名保存返回 `409`；分组与组内属性均可拖拽排序。
  2. 分组下经「关联要素」从数据要素库选入属性；新增 1 个分组后属性表的分组计数增加 1。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 分组名 | String | 是 | ≤ 64 字符 |
  | 顺序号 | Integer | 是 | — |
  | 属性数 | Integer | 是 | 只读 |
- **来源**：§5.1.4.3.1.2.3

### REQ-TYPE-004 移除属性定义不删除数据要素

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望移除属性定义时不误删数据要素本身，以便数据要素可被其他类型继续复用。
- **验收标准**：
  1. 从类型中【删除】1 条属性只删除该类型对该数据要素的属性定义，数据要素本身仍在数据要素库中存在，其使用情况计数减 1。
  2. 勾选 3 条属性批量删除时 3 条一次性移除，属性表行数减少 3。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 属性定义 ID | String | 是 | — |
  | 数据要素 | String | 是 | — |
  | 删除范围 | Enum(属性定义/数据要素) | 是 | 固定为属性定义 |
- **来源**：§5.1.4.3.1.2.3

## 数据要素与数据类型

### REQ-TYPE-005 数据要素名称全局唯一且不可改

- **优先级**：必须
- **用户故事**：作为平台管理员，我希望数据要素名称全局唯一且创建后不可修改，以便跨类型的属性引用保持稳定。
- **验收标准**：
  1. 以已存在名称创建数据要素返回 `409`；对已保存数据要素提交改名请求返回 `409`。
  2. 系统预定义数据要素仅 `要素标签` 允许修改，其余字段只读；标签保存后属性表对应列显示新标签。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 数据要素名称 | String | 是 | ≤ 64 字符，全局唯一，创建后只读 |
  | 要素标签 | String | 是 | — |
  | 说明 | Text | 否 | — |
- **来源**：§5.1.5.2

### REQ-TYPE-006 数据定义与数据类型

- **优先级**：必须
- **用户故事**：作为平台管理员，我希望数据定义以数据类型与输入类型刻画，以便数据要素获得一致的录入约束。
- **验收标准**：
  1. 数据定义分基本类型与数据选择器 2 类；基本类型的 `数据类型` 恰含 `String` 与 `Integer` 2 项，`输入类型` 恰含单行文本、多行文本、下拉框、单选输入、多选输入、复(勾)选框 6 项。
  2. 数据定义创建后不可修改；未被使用的数据定义可删除，删除后引用它的数据要素创建请求返回 `404`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 数据定义名称 | String | 是 | — |
  | 数据类型 | Enum(String/Integer) | 是 | — |
  | 长度 | Integer | 否 | — |
  | 输入类型 | Enum | 是 | 单行文本/多行文本/下拉框/单选输入/多选输入/复(勾)选框 |
- **来源**：§5.1.5.1

### REQ-TYPE-007 数据要素使用情况与删除保护

- **优先级**：必须
- **用户故事**：作为平台管理员，我希望删除数据要素前查询其使用情况并阻止在用项被删，以便不破坏已有类型属性与符号引用。
- **验收标准**：
  1. 删除前查询使用情况返回 `类型属性引用数`、`符号标签引用数` 与动态数据集条数 3 项计数；任一计数大于 0 或为系统预定义要素时删除返回 `DATA_ELEMENT_IN_USE`。
  2. 已使用的数据要素不能修改名称与数据定义；小数位由 4 改为 2 时按四舍五入截断，并在保存前提示该操作不可恢复。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 数据要素 | String | 是 | — |
  | 类型属性引用数 | Integer | 是 | 只读 |
  | 符号标签引用数 | Integer | 是 | 只读 |
  | 可删除 | Boolean | 是 | 只读 |
- **来源**：§5.1.5.2

## 属性级别与默认值

### REQ-TYPE-008 属性级别为可选信息或必选信息

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望属性级别在可选信息与必选信息之间切换，以便控制实例数据的完整性要求。
- **验收标准**：
  1. 类型编辑器属性表「级别」列下拉恰有 `可选信息` 与 `必选信息` 2 个选项，默认 `可选信息`；切换后该行立即显示新值。
  2. 级别为 `必选信息` 的属性在实例保存时为空则返回 `REQUIRED_ATTRIBUTE_MISSING`，填写后保存通过。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 级别 | Enum(可选信息/必选信息) | 是 | 默认 可选信息 |
  | 要素标签 | String | 是 | — |
  | 数据要素 | String | 是 | — |
- **来源**：§5.1.4.3.1.2.3

### REQ-TYPE-009 属性默认值与上溯取值

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望未设默认值的属性沿类型树向上取值，以便默认值集中定义且实例填充一致。
- **验收标准**：
  1. 类型属性未设默认值时沿类型树向上取最近 1 个有默认值的父类型；新建实例时属性面板显示的默认值与解析结果一致。
  2. 整条类型链均无默认值时取数据定义的空值，输入框显示为空；此时 `必选信息` 级别属性为空会阻止实例提交。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 默认值 | String | 否 | — |
  | 默认值来源 | Enum(本类型/父类型/数据定义) | 是 | 只读 |
  | 继承层级 | Integer | 是 | 只读 |
- **来源**：§5.1.4.3.1.2.3

## 属性拼接

### REQ-TYPE-010 属性拼接语法

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望用 `&` 连接数据要素并以英文单引号书写常量，以便把多个要素合成为 1 个属性值。
- **验收标准**：
  1. 表达式 `Des_Pipe_Specification & Des_Sequence_Number` 校验通过；`Des_Pipe_Specification &'/'&'装置区'` 等带常量表达式同样可保存。
  2. 常量缺右单引号或表达式含非法记号时保存返回 `CONCAT_SYNTAX_ERROR` 并指出出错位置。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 拼接表达式 | String | 是 | 语法见下表 |
  | 分隔符 | String | 否 | — |
  | 结果类型 | Enum(文本) | 是 | 固定为文本 |
- **来源**：§5.1.4.3.1.2.4

语法规则表：

| 语法元素 | 写法 | 示例 |
| --- | --- | --- |
| 要素引用 | 直接书写数据要素名 | `Des_Pipe_Specification` |
| 常量 | 英文单引号包裹，可为文本、数字、符号、空格 | `'/'`、`'装置区'` |
| 连接符 | 使用 `&` 连接相邻两项 | `A & B` |

### REQ-TYPE-011 属性拼接求值与循环引用保护

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望拼接在保存时求值并能检出循环引用，以便派生属性可靠且不陷入死循环。
- **验收标准**：
  1. 对象保存时拼接表达式求值并写入派生属性；求值失败不写入结果，返回 `CONCAT_EVAL_ERROR` 并指出出错的数据要素名。
  2. 表达式引用自身或形成环形依赖时保存返回 `CONCAT_CYCLE`，错误信息中列出环上至少 2 个数据要素名。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 求值时机 | Enum(保存时/实时) | 是 | — |
  | 循环检测 | Boolean | 是 | 固定 true |
  | 错误码 | String | 是 | 只读 |
- **来源**：新增设计

## 类型与符号的关系

### REQ-TYPE-012 类型与符号多对多映射

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望类型与符号建立多对多映射，以便同一类型按场景选用不同图形表达。
- **验收标准**：
  1. 1 个类型可选用多个符号，1 个符号可服务多个类型；符号的属性标签经 `标记` 引用数据要素，同一数据要素可在多个符号标签中复用。
  2. 符号标签含 `标记`、`提示`、`默认`、`位置` 4 个字段；被引用后的符号名称不可修改，修改请求返回 `409`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 符号 | String | 是 | — |
  | 类型编码 | String | 是 | — |
  | 标记 | String | 是 | — |
  | 提示 | String | 否 | — |
  | 默认 | String | 否 | — |
  | 位置 | Enum(上/下/左/右) | 是 | — |
- **来源**：§5.1.4.3.2.2.3.5

### REQ-TYPE-013 类型变更对既有符号实例的影响

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望类型变更不重建既有实例且删除类型受实例计数保护，以便存量图纸数据不受破坏。
- **验收标准**：
  1. 类型属性新增或级别变更后已存在实例不重建，仅下次打开并保存时按新属性集校验；新增 `必选信息` 属性时，缺失值实例数在类型编辑器保存前以提示形式给出。
  2. `类型编码` 不可改，实例的类型引用不发生迁移；类型删除时其下实例转为「未知类型」并计数，实例数大于 0 时阻止删除并返回 `TYPE_IN_USE`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 受影响实例数 | Integer | 是 | 只读 |
  | 未知类型实例数 | Integer | 是 | 只读 |
  | 处理动作 | Enum(仅告警/阻止保存) | 是 | — |
- **来源**：新增设计

## 规则继承

### REQ-TYPE-014 位号规则与颜色规则向上继承

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望位号规则与颜色规则沿类型树向上继承，以便规则在合适的层级统一定义。
- **验收标准**：
  1. 位号规则与颜色规则沿类型树自叶向根上溯取最近 1 条有效定义；当前类型无规则时使用父类型规则，整条链均无规则时位号走手动录入、颜色取符号默认色。
  2. 同一类型同时只有 1 条有效位号规则，启用 1 条则其余自动置为无效；继承结果可在子类型节点上预览并显示来源类型编码。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 规则类型 | Enum(位号规则/颜色规则) | 是 | — |
  | 生效来源类型 | String | 是 | 只读 |
  | 继承层级 | Integer | 是 | 只读 |
- **来源**：§6.1.5.1

### REQ-TYPE-015 子类型覆盖与父类型变更边界

- **优先级**：必须
- **用户故事**：作为类型库管理员，我希望子类型定义的规则优先于父类型且不被父级变更冲掉，以便局部定制与全局管理并存。
- **验收标准**：
  1. 子类型已定义同名规则时优先于父类型；父类型新增或修改规则不覆盖子类型已定义的同名规则，仅影响未定义规则的子类型。
  2. `覆盖标记` 为已覆盖时父类型规则变更后该子类型预览值不变；未覆盖的子类型预览值更新为父类型新值。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 覆盖标记 | Boolean | 是 | — |
  | 规则类型 | Enum(位号规则/颜色规则) | 是 | — |
  | 最后变更时间 | DateTime | 是 | 只读 |
- **来源**：新增设计
