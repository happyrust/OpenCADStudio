# 数据管理与规则检查需求

本文档定义 P&ID 平台的对象数据管理与设计规则检查需求，共 16 条，按 9 个小节组织。编号规则见 `docs/pid-platform/requirements/00-overview.md`；位号生成规则与项目设置在 `docs/pid-platform/requirements/30-symbol-library-and-project-settings.md` 定义，对象绘制与放置行为在 `docs/pid-platform/requirements/40-drawing-and-drafting.md` 定义，材料清单聚合与发布门禁在 `docs/pid-platform/requirements/60-deliverables-and-publish.md` 定义，本文档不重复定义。

## 位号主数据与唯一性

每个带位号的对象实例在位号主数据中登记一行，位号是该实例在数据层的唯一主键，材料清单、拓扑连接与检查结果都按它汇聚。位号主数据字段表如下：

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| 位号 | String | 是 | ≤ 32 字符，主键 |
| 类型编码 | String | 是 | 取自类型库 |
| 所在图纸 | String | 是 | 图纸 ID |
| 所属 PBS 节点 | String | 是 | — |
| 状态 | Enum(有效/已删除) | 是 | 已删除进入冷却期 |
| 登记时间 | DateTime | 是 | 只读 |
| 冷却截止日 | Date | 条件必填 | 状态为已删除时必填 |

唯一性在项目级生效：同一项目内、跨全部图纸、同一类型下的两个实例不得登记相同位号；不同类型对象允许同值位号，例如管线 `L-1001` 与仪表回路 `L-1001` 分属不同类型互不影响。`位号唯一校验` 开关关闭时不做该验证。

位号生成沿用 `30-symbol-library-and-project-settings.md` 定义的 `格式名称`、`起始编码`、`增量`、`后缀递增`、`层级选择`、`拼接字段`、`位号唯一校验`、`自动弹窗` 八个字段。

### REQ-DATA-001 位号主数据登记与唯一键

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望位号在项目内只登记一次，以便材料清单与拓扑都以同一把主键汇聚。
- **验收标准**：
  1. 同一项目内重复登记位号 `P-1001` 时，保存返回 `TAG_DUPLICATED`，位号主数据行数不变。
  2. 登记 1 个对象实例后位号主数据行数增加 1，该行 `位号` 值与实例属性一致。
  3. 删除对象后该位号进入 30 天冷却期，冷却期内再次登记返回 `TAG_IN_COOLDOWN`，第 31 天起允许登记。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 位号 | String | 是 | ≤ 32 字符，项目内唯一主键 |
  | 状态 | Enum(有效/已删除) | 是 | 冷却期内保持已删除 |
  | 冷却截止日 | Date | 条件必填 | 删除日 + 30 天 |
- **来源**：新增设计

### REQ-DATA-002 位号唯一校验的项目级生效范围

- **优先级**：必须
- **用户故事**：作为项目管理员，我希望位号唯一校验的生效范围可配置为项目级或图纸级，以便校验口径与项目约定一致。
- **验收标准**：
  1. `位号唯一校验` 开启时执行同类型唯一性验证：同项目同类型下登记第 2 个 `P-1001` 返回 `TAG_DUPLICATED`；关闭时同样操作不验证，保存成功且主数据行数增加 1。
  2. `作用范围` 可设为 `项目级` 或 `图纸级`，默认 `项目级`。
  3. `项目级` 校验跨全部 PBS 节点：在另一 PBS 节点的图纸登记同值位号返回 `TAG_DUPLICATED`；`图纸级` 下仅当前图纸内查重，跨图同值不冲突。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 位号唯一校验 | Boolean | 是 | 默认开启 |
  | 作用范围 | Enum(项目级/图纸级) | 是 | 默认项目级 |
  | 查重范围 | String | 是 | 只读，项目级 = 全部 PBS 节点 |
- **来源**：§6.1.5.1.3

## 位号冲突处理

位号冲突在以下时机检出：登记新实例、复制图纸或对象、导入图纸、修改位号前缀重算时，同类型唯一性验证发现位号重复。检出后该实例 `位号` 显示为 `？`——`？` 是冲突标记，不能作为位号保存——并在校验结果中记入 1 条 `DR-004` 错误。冲突有三条解决路径：手工改位号（直接在属性表改为不冲突值）、设备关联（跨图纸同一设备关联共享属性，而不是复制位号）、批量重编（对选中实例按位号规则的 `起始编码` 与 `增量` 重新编号）。

### REQ-DATA-003 重复位号的检出与问号标记

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望重复位号在图面上以 `？` 标出并进入校验结果，以便冲突一眼可见且不被误存。
- **验收标准**：
  1. 检测到同类型位号重复时该实例 `位号` 显示为 `？`，校验结果中出现 1 条 `DR-004` 错误级结果。
  2. 把 `？` 作为位号提交保存被拒绝，返回 `TAG_INVALID`，实例保持冲突态。
  3. 冲突实例改位号为不重复值后 `位号` 显示正常值，`DR-004` 结果数减少 1。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 位号 | String | 是 | 冲突时显示 `？`，禁止保存 |
  | 冲突实例数 | Integer | 是 | 只读 |
  | 冲突来源 | Enum(复制/导入/改前缀/登记) | 是 | — |
- **来源**：§6.1.5.1.3

### REQ-DATA-004 位号冲突的解决与设备关联替代

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望冲突位号有三条互不相同的解决路径，以便按场景选择成本最低的处理方式。
- **验收标准**：
  1. 冲突实例提供 3 条解决路径：`手工改位号`、`设备关联`、`批量重编`。
  2. 手工改位号：把冲突实例 `位号` 改为未占用值后保存成功，冲突标记消失，`位号` 显示新值。
  3. 跨图纸同一设备位号冲突时改用 `设备关联`：2 个同型实例关联为同一设备后 `属性共享` 显示 `是`，不再要求两份位号各占一行。
  4. 批量重编：选中 5 个冲突实例按 `起始编码` = 101、`增量` = 1 重排后，位号依次为 `P-101` 至 `P-105`，冲突实例数变为 0。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 解决方式 | Enum(手工改位号/设备关联/批量重编) | 是 | 恰 3 项 |
  | 起始编码 | Integer | 条件必填 | 批量重编时 |
  | 增量 | Integer | 条件必填 | 批量重编时，≥ 1 |
  | 关联设备位号 | String | 条件必填 | 设备关联时 |
- **来源**：新增设计

## 对象属性管理器

对象属性管理器呈三区布局：左侧为当前图纸产生的符号类型及其层级树；右上为所选类型（含其子类）的实例列表；右下为当前对象的全部属性。单击实例行的 `位号`，图面对象高亮居中并锁定视图；双击属性行就地编辑。

### REQ-DATA-005 对象属性管理器的类型树与实例列表

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望属性管理器按类型树、实例列表、属性表三区呈现当前图纸对象，以便批量查看与编辑属性。
- **验收标准**：
  1. 界面恰为 3 个分区：左侧为当前图纸产生的符号类型及其层级树，右上为所选类型的实例列表，右下为当前对象的全部属性表。
  2. 在类型树选中 1 个含 2 个子类的父类型时，实例列表行数等于该父类型及全部子类实例数之和。
  3. 单击实例行 `位号`，图面对象自动高亮居中且视图锁定；双击属性行就地编辑，保存后属性表显示新值。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 类型树 | Tree | 是 | 层级含子类 |
  | 实例列表 | Table | 是 | 首列为 `位号` |
  | 选中实例 | ObjectRef | 是 | 只读 |
  | 属性表 | Table | 是 | 当前对象全部属性 |
- **来源**：§6.2.2.3.6

### REQ-DATA-006 属性批量编辑与表格回写

- **优先级**：应该
- **用户故事**：作为工艺设计人员，我希望把当前图纸全部实例导出为表格批量编辑后再导入回写，以便批量修改属性不逐条点选。

## 检索与查询

平台提供四种检索入口，各自面向不同场景：全文检索匹配文档内容与属性值，用于跨资料查找；列表模糊搜索在管理器列表内按子串过滤，用于缩小当前列表；多条件高级搜索以 AND 组合多个条件，用于精确筛选；图纸内位号检索在图纸预览或编辑界面按位号定位对象，用于图面跳转。

## 规则引擎模型

规则引擎采用 规则 → 规则集 → 规则包 三级结构：规则是单条可求值的检查条件；规则集是有序的规则组，可整体启停；规则包是分发单元，声明依赖的图例标准版本。规则按用途分为 `配置类` 与 `设计类` 两类：配置类约束设置页字段取值，设计类作用于图面对象实例。

规则元数据字段：

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| 规则 ID | String | 是 | 形如 `DR-001`，规则包内唯一 |
| 名称 | String | 是 | ≤ 64 字符 |
| 作用对象 | String | 是 | 类型编码或 `对象实例` |
| 严重度 | Enum(错误/警告/提示) | 是 | 三值枚举，无第四级 |
| DSL 表达式 | String | 是 | 符合规则 DSL 文法，保存时解析 |
| 启用状态 | Boolean | 是 | 默认启用 |
| 作用域 | Enum(项目/PBS 节点/图纸/类型) | 是 | 恰 4 选 1 |
| 来源 | Enum(内置/复制修改/新建) | 是 | — |
| 规则类别 | Enum(配置类/设计类) | 是 | — |

- **来源**：新增设计

## 规则 DSL

规则 DSL 是设计类规则条件表达式的文法，逐字定义如下：

```ebnf
(* 设计规则条件表达式 —— 新增设计 *)
expression    = or_expr ;
or_expr       = and_expr { "OR" and_expr } ;
and_expr      = not_expr { "AND" not_expr } ;
not_expr      = [ "NOT" ] atom ;
atom          = "(" expression ")" | comparison ;
comparison    = path operator operand ;
operator      = "=" | "!=" | ">" | "<" | ">=" | "<="
              | "IN" | "NOT IN" | "MATCH" | "NOT MATCH" ;
operand       = value | path | "(" operand { "," operand } ")" ;
value         = string | number | enum_ref | boolean | "NULL" ;
path          = segment { "." segment } ;
segment       = identifier ;
identifier    = letter { letter | digit | "_" } ;
string        = '"' { character } '"' ;
number        = [ "-" ] digit { digit } [ "." digit { digit } ] ;
enum_ref      = "#" identifier ;
boolean       = "TRUE" | "FALSE" ;
letter        = "A".."Z" | "a".."z" | "一".."鿿" ;
digit         = "0".."9" ;
```

属性路径以对象自身为根，`.` 逐级下钻；跨对象取值经关系属性，如 `所属设备.位号`、`所属管线.管道等级.最大公称压力`。比较运算符覆盖相等、不等、大小比较、集合归属（`IN`、`NOT IN`）与模式匹配（`MATCH`、`NOT MATCH`）；逻辑连接符为 `AND`、`OR`、`NOT`，可用括号改变优先级；取值分字符串、数值、枚举引用、布尔与 `NULL` 五类。

语义约定：

- 关键字、逻辑连接符、运算符一律大写；字符串用双引号；枚举引用以 `#` 前缀指向项目主数据取值。
- 求值结果为三值逻辑真/假/未知；`NULL` 表示属性未赋值。规则在条件求值为真时命中并产生一条违规。
- 解析失败必须在保存规则时拒绝，返回错误码 `DSL_PARSE_ERROR` 并指出出错位置；不得保存半解析的规则。

完整示例：表达式 `(设计温度 > 200 OR 介质 = #蒸汽) AND 绝热等级 = NULL`；示例对象为管线 `L-2001`，其 `设计温度` = 260、`介质` = #工艺水、`绝热等级` 未赋值。求值：`设计温度 > 200` 为真，`介质 = #蒸汽` 为假，左支为真；`绝热等级 = NULL` 为真；整体为真，规则命中，产生 1 条 `DR-025` 违规。

### REQ-DATA-012 规则 DSL 的语法与解析错误处理

- **优先级**：必须
- **用户故事**：作为规则配置人员，我希望 DSL 表达式在保存时即被解析并报告出错位置，以便错误规则不流入检查执行。
- **验收标准**：
  1. 合法表达式 `管道等级 = NULL` 保存成功并生成语法树，解析结果返回 `OK`。
  2. 非法表达式 `管道等级 ==` 保存被拒绝，返回 `DSL_PARSE_ERROR` 并携带出错位置的行内偏移，规则表行数不变。
  3. 表达式引用不存在的关系路径 `所属泵.位号` 时保存被拒绝，返回 `DSL_PARSE_ERROR` 并指出该路径位置。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | DSL 表达式 | String | 是 | 符合规则 DSL 文法 |
  | 解析结果 | Enum(OK/DSL_PARSE_ERROR) | 是 | 只读 |
  | 出错偏移 | Integer | 条件必填 | 解析失败时的行内偏移 |
- **来源**：新增设计

## 触发时机

设计规则检查有三种触发时机，阻塞行为各不相同：

| 触发时机 | 执行范围 | 阻塞行为 | 结果处理 |
| --- | --- | --- | --- |
| 按需 | 当前图纸或选中的 PBS 节点 | 不阻断，由用户主动发起 | 结果写入检查结果集，可在结果面板定位到对象 |
| 保存前 | 当前图纸 | 阻断，存在错误级结果时保存返回 `RULE_BLOCKED` 且图纸保持修改前状态 | 弹窗列出错误项并要求逐条处理 |
| 发布前 | 待发布的全部图纸与项目主数据 | 阻断，存在错误级结果时发布任务返回 `PUBLISH_BLOCKED` | 生成发布门禁报告并写入审计日志 |

### REQ-DATA-013 按需保存前与发布前三种触发时机

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望规则检查按按需、保存前、发布前三种时机运行且阻塞行为各异，以便检查强度与场景匹配。
- **验收标准**：
  1. `按需` 触发不阻断：在选中图纸上发起检查后结果写入检查结果集，用户可继续编辑。
  2. `保存前` 触发阻断：当前图纸存在 `错误` 级结果时保存返回 `RULE_BLOCKED`，图纸保持修改前状态。
  3. `发布前` 触发阻断：待发布范围存在 `错误` 级结果时发布任务返回 `PUBLISH_BLOCKED`，发布包不生成。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 触发时机 | Enum(按需/保存前/发布前) | 是 | 恰 3 值 |
  | 是否阻断 | Boolean | 是 | 只读，按需为否 |
  | 阻断错误码 | String | 条件必填 | `RULE_BLOCKED` 或 `PUBLISH_BLOCKED` |
- **来源**：新增设计

## 结果模型

每次检查产出一份检查结果集，单条检查结果字段如下：

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| 规则 ID | String | 是 | 形如 `DR-001`，取自设计规则清单 |
| 对象引用 | ObjectRef | 是 | 类型编码、位号与图纸 ID 三元组，唯一定位一个对象实例 |
| 严重度 | Enum(错误/警告/提示) | 是 | 三值枚举，无第四级 |
| 消息 | String | 是 | ≤ 200 字符，含规则名称与违规定位描述 |
| 建议修复 | String | 否 | ≤ 200 字符，给出可执行的修复动作 |

结果集另有 `规则集版本` 与 `检查时间` 两个外层字段，用于结果回溯与版本对账。
