# 协同与权限需求

本文档定义 P&ID 平台的协同与权限需求，共 12 条，按 6 个小节组织；需求编号规则见 `docs/pid-platform/requirements/00-overview.md`。平台级的三级授权链条目是 `REQ-PLAT-010`，本文档在图纸粒度上展开；图纸权限的生命周期入口是 `REQ-DRW-007`（定义于 `docs/pid-platform/requirements/40-drawing-and-drafting.md`），本文档补齐它留下的权限粒度。权限的五个字段名 `角色`、`PBS 节点`、`图纸状态`、`允许`、`拒绝` 以本文档为权威定义处。

## 三级授权链

授权判定沿三级收敛，判定顺序恰为 3 级：第一级 `角色权限`，即功能权限，按角色 × 操作查权限矩阵；第二级 `PBS 节点 ACL`，沿 PBS 树自根向下取最近的一条显式 ACL，节点未配置时继承父节点，根节点也无配置时该级视为拒绝；第三级 `图纸状态`。

判定式为 `判定 = 角色权限 × PBS 节点 ACL × 图纸状态`：三级同时为允许才放行，任一级拒绝即整体拒绝，响应返回首个拒绝级别与对应错误码。

与 `REQ-DRW-007` 的衔接：`REQ-DRW-007` 定义图纸权限的生命周期入口与最低权限集（`查看`、`编辑`、`导出`、`删除` 4 项）以及「未配置时 `继承自` PBS 节点」的行为；本节定义该权限集的判定链与角色 × 操作矩阵，两处不重复定义。

判定示例：

| 角色权限 | PBS 节点 ACL | 图纸状态 | 判定 | 拒绝级别 |
| --- | --- | --- | --- | --- |
| 允许 | 允许 | 单人编辑 | 允许 | — |
| 允许 | 允许 | 只读 | 拒绝 | 图纸状态 |
| 允许 | 拒绝 | 协同编辑 | 拒绝 | PBS 节点 ACL |
| 拒绝 | 允许 | 单人编辑 | 拒绝 | 角色权限 |
| 允许 | 允许 | 协同编辑 | 允许 | — |

## 图纸状态

图纸状态枚举恰为 3 个值：`单人编辑`、`协同编辑`、`只读`。这里的 `图纸状态` 专指图纸的编辑会话状态，是权限判定的第三级；它与 `REQ-DRW-003` 定义的 `生命周期状态`（设计中、已校核、已批准、已发布）是两个不同字段，不得混用同一取值域。状态决定一张图纸允许的编辑会话数与可写性：

| 图纸状态 | 含义 | 可写 | 允许的编辑会话数 |
| --- | --- | --- | --- |
| 单人编辑 | 同一时刻仅 1 个编辑会话持有写权 | 是 | 1 |
| 协同编辑 | 多个编辑会话共享同一基线修订号并发写入 | 是 | 多 |
| 只读 | 禁止一切写入，仅可查看与导出 | 否 | 0 |

状态迁移规则：`单人编辑` 与 `协同编辑` 双向切换由项目管理员或图纸持有者执行；任一可编辑状态转为 `只读` 由发布、锁定、越权 3 种情形触发；`只读` 转 `协同编辑` 需 `授权配置` 操作权限。

- **来源**：§6.2.2.1.2.1.6

## 并发编辑策略

并发处置按「状态 × 事件 → 动作」表执行：

| 状态 | 事件 | 动作 |
| --- | --- | --- |
| 单人编辑 | 其他会话申请占用同一位号 | 拒绝申请并返回当前占用者与位号 |
| 协同编辑 | 其他会话申请占用同一位号 | 授予首个申请者占用并广播变更，其余申请进入等待 |
| 协同编辑 | 位号占用超时未续期，等待释放 | 释放占用并写入审计 |
| 单人编辑 | 图纸被他人锁定，本端会话只读降级 | 降级为只读并拒绝写入，返回 `409` |
| 协同编辑 | 同一字段被 2 方修改，形成属性合并冲突 | 生成冲突条目，等待人工裁决 |
| 协同编辑 | 删除已被其他对象引用的对象 | 拒绝删除并返回引用方清单 |
| 只读 | 对已发布基线发起修改 | 拒绝写入，须新建修订版本 |
| 协同编辑 | 会话心跳连续 6 次缺失 | 会话置为失效并释放其占用 |

并发模型有两条不变量：同一时刻同一张图纸最多 1 个 `单人编辑` 会话；同一张图纸的多个 `协同编辑` 会话共享同一 `基线修订号`。

## 冲突检测与解决

冲突分 3 类，判定条件与默认解决方式如下：

| 冲突类型 | 判定条件 | 默认解决 | 是否需人工 |
| --- | --- | --- | --- |
| 对象级 | 同一对象被一方删除、另一方仍提交修改 | 删除生效，修改方收到通知与被覆盖原值 | 否 |
| 属性级 | 同一字段被 2 方写入不同值 | 按 `基线修订号` 判定，落后方让位 | 否 |
| 拓扑级 | 连接关系双方变更后管路拓扑不一致 | 生成冲突条目等待裁决 | 是 |

解决顺序固定为三段：① 不同字段的修改自动合并，互不覆盖；② 同一字段被两方修改时按 `基线修订号` 判定，落后的一方让位并由系统记录被覆盖的原值；③ 仍无法判定时生成冲突条目进入冲突列表，由项目管理员裁决，裁决结果与双方原值写入审计日志。

## 编辑会话

编辑会话字段如下：

| 字段 | 类型 | 说明 | 约束 |
| --- | --- | --- | --- |
| 会话 ID | UUID | 会话全局标识 | 全局唯一 |
| 图纸 | String | 会话绑定的图纸 | — |
| 持有者 | String | 建立会话的用户 | — |
| 模式 | Enum | 会话的编辑模式 | ∈ 单人编辑、协同编辑、只读 |
| 状态 | Enum | 会话生命周期状态 | ∈ 活跃、失效、已接管 |
| 心跳间隔 | Integer | 客户端心跳周期，单位秒 | 固定 15 |
| 超时阈值 | Integer | 判失效的无心跳时长，单位秒 | 固定 90 |
| 基线修订号 | Integer | 会话共享的修订基线 | 同图协同会话一致 |

客户端每 15 秒发送一次心跳；连续 6 次（即 90 秒）无心跳的会话判 `失效`，其位号占用与图纸锁自动释放；同一图纸同一模式重新打开时可接管失效会话，接管写入审计。仓库现有 `src/io/edit_lock.rs` 提供文件租约与外部变更指纹，它只是图纸状态一级的实现细节，不构成本节的协同协议，不得据此认定协同能力已存在。

## 权限矩阵

本节不复刻参考产品手册的操作编号体系：手册的功能权限表只列出 1–7 项，而正文却引用第 4–12 项，手册自身不自洽；图纸权限只有一句「对图纸进行权限管理」，粒度无法从手册还原。因此本节改为自定义「角色 × 操作」二维矩阵，本矩阵与其操作集合标注为 `新增设计`。

### REQ-COLL-011 角色与操作二维权限矩阵

- **优先级**：必须
- **用户故事**：作为权限管理员，我希望以 5 个角色 × 8 类操作的二维矩阵表达功能权限，以便每一格都有确定判定。
- **验收标准**：
  1. 权限矩阵为 5 个角色 × 8 类操作的二维表，单元格取值恰为 `允许`、`拒绝` 2 值，不允许为空或第三值。
  2. 矩阵是三级授权链第一级 `角色权限` 的数据源：单元格为 `拒绝` 的操作在角色权限级直接拒绝，不再进入后两级判定。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 角色 | String | 是 | 5 个角色之一 |
  | 操作 | Enum | 是 | 8 类操作之一 |
  | 判定 | Enum(允许/拒绝) | 是 | — |
- **来源**：新增设计

### REQ-COLL-012 拒绝优先与最小权限

- **优先级**：必须
- **用户故事**：作为权限管理员，我希望同一操作在不同来源结论冲突时以拒绝为准，以便权限默认收敛到最小集。
- **验收标准**：
  1. 同一角色在用户级与角色级两级配置中对同一操作同时出现 `允许` 与 `拒绝` 时，判定结果为 `拒绝`。
  2. 未在权限矩阵中登记的操作默认 `拒绝`；登记前任何角色调用该操作返回 `403`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 操作 | String | 是 | — |
  | 用户级判定 | Enum(允许/拒绝/未配置) | 是 | — |
  | 角色级判定 | Enum(允许/拒绝/未配置) | 是 | — |
  | 最终判定 | Enum(允许/拒绝) | 是 | 只读 |
- **来源**：新增设计
