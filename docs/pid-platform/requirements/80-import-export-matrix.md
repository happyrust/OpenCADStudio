# 导入导出矩阵需求

本文档定义 P&ID 平台各数据类别的导入导出能力矩阵与格式限制，共 8 条，按 2 个小节组织；需求编号规则见 `docs/pid-platform/requirements/00-overview.md`。图纸输出格式的能力细节已在 `docs/pid-platform/requirements/60-deliverables-and-publish.md` 的导出矩阵定义，本文档只从数据类别维度给出导入与导出的对应关系，不重复格式能力描述。

## 导入导出矩阵

各数据类别的导入导出对应关系如下，多值以顿号分隔，无该方向能力的单元格标 `不支持`：

| 数据类别 | 导入 | 导出 | 支持程度 | 限制 |
| --- | --- | --- | --- | --- |
| 图纸 | DWG、SVG | DWG、DXF、PDF、SVG | 完整支持 | 图纸文件名唯一，导入前须选定图例标准 |
| P&ID 对象与属性 | Excel（XLSX）、CSV、JSON | Excel（XLSX）、CSV、JSON | 完整支持 | 按位号匹配写回，未匹配行进入错误文件 |
| 项目主数据 | Excel（XLSX）、CSV、JSON | Excel（XLSX）、CSV、JSON | 完整支持 | 按主数据类别分表，编码冲突时整行拒绝 |
| 配置包 | JSON | JSON | 部分支持 | 导入前须通过授权校验；参考产品的 ZIP 载体须先解包为 JSON 清单再按本行导入（见 `REQ-MIG-003`） |
| 报表与材料清单 | 不支持 | Excel（XLSX）、CSV、PDF | 部分支持 | 导出须选定报表模板 |
| 符号库 | JSON | JSON | 部分支持 | 导入时校验类型库依赖，缺失类型的符号拒绝写入 |
| 类型库与规则 | Excel（XLSX）、CSV、JSON | Excel（XLSX）、CSV、JSON | 完整支持 | 规则表达式须通过语法校验 |

### REQ-IO-001 导入导出矩阵的数据类别覆盖

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望每种数据类别的导入导出格式与限制逐项明确，以便交换前已知边界。
- **验收标准**：
  1. 矩阵恰含 7 行数据类别：图纸、P&ID 对象与属性、项目主数据、配置包、报表与材料清单、符号库、类型库与规则。
  2. 矩阵中格式覆盖 `DWG`、`DXF`、`PDF`、`SVG`、`Excel（XLSX）`、`CSV`、`JSON` 7 种；`支持程度` 列恰取 `完整支持`、`部分支持`、`不支持` 3 值之一，每行 `限制` 非空。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 数据类别 | String | 是 | 7 类之一 |
  | 导入格式 | List | 是 | 可为空，空即不支持 |
  | 导出格式 | List | 是 | 可为空，空即不支持 |
  | 支持程度 | Enum(完整支持/部分支持/不支持) | 是 | 恰 3 值 |
  | 限制 | String | 是 | 非空 |
- **来源**：新增设计

### REQ-IO-002 图纸导入格式与文件名唯一

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望图纸导入限定格式并强制文件名唯一，以便导入结果可归档可检索。
- **验收标准**：
  1. 图纸导入格式恰为 `DWG`、`SVG` 2 种（与 `REQ-DRW-004` 的扩展名约束一致）；导入前须选定 `图例标准`，未选定执行导入返回 `LEGEND_NOT_SELECTED`。
  2. 同一 PBS 节点下图纸文件名必须唯一；重名导入被拒绝并返回 `NAME_DUPLICATED` 与既有图纸名。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 图纸文件 | File | 是 | — |
  | 格式 | Enum(DWG/SVG) | 是 | 恰 2 值 |
  | 图例标准 | String | 是 | 导入前选定 |
  | 目标节点 | String | 是 | PBS 节点 |
  | 文件名 | String | 是 | 节点内唯一 |
- **来源**：§6.2.2.1.2.1.2

### REQ-IO-003 图纸导出四格式

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望同一图纸能导出四种格式，以便覆盖编辑、交换、归档与预览用途。
- **验收标准**：
  1. 图纸导出格式恰为 `DWG`、`DXF`、`PDF`、`SVG` 4 种，各格式能力与约束见 `docs/pid-platform/requirements/60-deliverables-and-publish.md` 的导出矩阵。
  2. 未选定输出格式执行导出返回 `FORMAT_NOT_SELECTED`；`SVG` 每次仅导出当前图纸 1 张。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 图纸 | String | 是 | — |
  | 导出格式 | Enum(DWG/DXF/PDF/SVG) | 是 | 恰 4 值 |
  | 导出范围 | Tree | 是 | 复选框树 |
  | 输出目录 | String | 是 | 本机或项目文档库 |
- **来源**：§6.2.2.4.1

## 格式支持与限制

按格式展开的双向能力表。本表 `支持程度` 合并导入与导出两个方向判定：任一方向不可用、或可用方向有语义损失时记 `部分支持`。`docs/pid-platform/requirements/60-deliverables-and-publish.md` 的导出矩阵只判导出方向，故 PDF、DXF、SVG 在该表记 `完整支持`；两处按各自口径判定，不构成冲突。

| 格式 | 导入方向 | 导出方向 | 支持程度 | 限制 |
| --- | --- | --- | --- | --- |
| DWG | 图纸 | 图纸 | 完整支持 | 不写位号主数据 |
| DXF | 不支持 | 图纸 | 部分支持 | 仅作交换出口，版本可选 R14 至 2018，不保留 P&ID 语义扩展数据 |
| PDF | 不支持 | 图纸、报表 | 部分支持 | 只读，不含对象属性 |
| SVG | 图纸 | 图纸 | 部分支持 | 仅当前图纸，嵌入字体转路径 |
| Excel（XLSX） | 对象属性、项目主数据、类型库 | 对象属性、材料清单、报表 | 完整支持 | 列映射由报表模板声明 |
| CSV | 对象属性、项目主数据、类型库 | 对象属性、材料清单、校验结果 | 完整支持 | UTF-8 编码，不含样式 |
| JSON | 对象属性、项目主数据、配置包、符号库、类型库与规则 | 对象属性、校验结果、配置包、符号库、类型库与规则 | 完整支持 | 顶层必须含 `schemaVersion` |

### REQ-IO-004 属性表格导入导出与行级错误定位

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望属性表格导入时逐行校验并定位错误行号，以便修正后只重导错误行。
- **验收标准**：
  1. `Excel（XLSX）` 与 `CSV` 表格按表头列名映射到 `数据要素`；表头存在无法映射的列时导入被拒绝并返回列名清单。
  2. 逐行校验失败的行写入错误文件，逐行标注 `行号` 与 `原因`；成功行按 `位号` 匹配实例写回属性，位号无实例的行标为 `未匹配`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 表头列 | String | 是 | 映射到数据要素 |
  | 行号 | Integer | 是 | ≥ 1 |
  | 原因 | String | 条件必填 | 失败行必填 |
  | 写入结果 | Enum(已写入/未匹配/失败) | 是 | 恰 3 值 |
- **来源**：§6.2.2.3.6

### REQ-IO-005 JSON 统一交换 schema 与版本号

- **优先级**：必须
- **用户故事**：作为集成开发者，我希望 JSON 交换文件带 schema 版本号且版本不受支持时明确报错，以便跨版本解析可控。
- **验收标准**：
  1. 导出 JSON 顶层必须含 `schemaVersion`，本期取值 `1.0`；读取方按 `schemaVersion` 分流到对应解析器。
  2. `schemaVersion` 缺失或取值不在支持集内时导入返回 `SCHEMA_VERSION_UNSUPPORTED`，文件不进入后续解析。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | schemaVersion | String | 是 | 本期取值 `1.0` |
  | 文件内容 | JSON | 是 | — |
  | 支持集 | List | 是 | 只读 |
- **来源**：新增设计

### REQ-IO-006 符号库导入导出与类型库依赖校验

- **优先级**：必须
- **用户故事**：作为项目管理员，我希望符号库以 JSON 整体迁入迁出且依赖类型先校验，以便换环境后不出现悬空符号。
- **验收标准**：
  1. 符号库以 `JSON` 单文件导入导出；导入时逐符号校验其声明的类型在目标 `类型库` 中存在，缺失类型的符号计入拒绝行数并列入导入报告。
  2. 导出内容含 `符号定义`、`连接点`、`属性标签` 3 类，缺任一类导出被拒绝并返回缺失类别名。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 符号定义 | JSON | 是 | — |
  | 类型依赖 | List | 是 | 逐符号声明 |
  | 连接点 | List | 是 | — |
  | 拒绝行数 | Integer | 是 | 只读 |
- **来源**：§5.1.4.3.2

### REQ-IO-007 配置包导入导出与授权校验

- **优先级**：必须
- **用户故事**：作为系统管理员，我希望配置包整体导出且导入前先过授权校验，以便跨环境迁移受控。
- **验收标准**：
  1. 配置包以 `JSON` 单文件导出；导入前校验调用者具备 `授权配置` 权限，不具备时导入返回 `403`。
  2. 配置包含 `类型库`、`符号库`、`位号规则`、`项目主数据` 4 类内容，包版本号随包携带且导入动作写入审计日志 1 条。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 配置包内容 | List | 是 | 恰 4 类 |
  | 包版本号 | String | 是 | 随包携带 |
  | 授权校验结果 | Enum(通过/拒绝) | 是 | 只读 |
  | 导入结果 | Enum(成功/失败) | 是 | 只读 |
- **来源**：§5.1.13.2.2.2.2

### REQ-IO-008 导入失败的错误文件与重导

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望导入失败时拿到逐行标注原因的错误文件并可只重导错误行，以便修正成本最低。
- **验收标准**：
  1. 校验失败时生成错误文件 1 份，逐行标注 `行号` 与 `原因`；`成功行数` 与 `失败行数` 之和等于源文件数据行数。
  2. 修正错误文件后可发起重导，重导只处理失败行；重导后 `成功行数` ≥ 1 时任务状态记为 `成功`，为 0 时记为 `失败`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 错误文件 | File | 条件必填 | 存在失败行时生成 |
  | 行号 | Integer | 是 | ≥ 1 |
  | 原因 | String | 是 | 逐行标注 |
  | 成功行数 | Integer | 是 | 只读 |
  | 失败行数 | Integer | 是 | 只读 |
- **来源**：新增设计
