# 图纸与绘图需求

本文档定义 P&ID 平台的图纸与绘图需求，共 30 条，按 13 个小节组织。编号规则见 `docs/pid-platform/requirements/00-overview.md`；符号、连接点、位号规则、打断符样式与项目主数据在 `docs/pid-platform/requirements/30-symbol-library-and-project-settings.md` 定义，位号唯一性与设计规则检查在 `docs/pid-platform/requirements/50-data-and-rule-engine.md` 定义，本文档不重复定义。

## PBS 层级

### REQ-DRW-001 PBS 层级创建与图纸挂接

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望在图纸管理中逐级创建 PBS 节点并把图纸挂接到节点下，以便图纸按装置与单元归口并能按层级检索。
- **验收标准**：
  1. 图纸管理界面左侧为 1 棵 PBS 层级树、右侧为当前层级的图纸列表；平铺视图下每张图纸显示 1 个预览缩略图；经【新建】下拉列表完成 PBS 层级创建与图纸新建。
  2. 层级节点类型恰为 `工厂`、`装置`、`单元` 3 种，可灵活创建并预定义层级关系；图纸挂接在所选目录节点下。
  3. 在同一父节点下新建重名节点返回 `409` 且树节点数不变。
  4. 在选中的 `单元` 节点下新建 1 张图纸后该节点 `图纸数` 增加 1，且该图纸只出现在该节点与其祖先节点的列表筛选中。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 节点名称 | String | 是 | ≤ 64 字符，同一父节点下唯一 |
  | 节点类型 | Enum(工厂/装置/单元) | 是 | 恰 3 级 |
  | 父节点 | String | 否 | 工厂节点为空 |
  | 图纸数 | Integer | 是 | 只读 |
- **来源**：§6.2.2.1

### REQ-DRW-002 PBS 节点维护与删除守卫

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望对 PBS 节点执行重命名、同级移动与受控删除，以便层级调整后图纸归口保持正确。
- **验收标准**：
  1. 节点重命名后其下全部图纸的 `所属 PBS 节点` 显示新名称；同级移动后 `父节点` 值不变、同级顺序更新。
  2. 删除含 3 张图纸的节点被拒绝并返回 `PBS_NODE_NOT_EMPTY`，节点仍在树中且 `图纸数` 不变。
  3. 删除 1 个 `图纸数` 与 `子节点数` 均为 0 的空节点后，同级节点数减少 1。
  4. `可否删除` 仅当 `图纸数` 与 `子节点数` 均为 0 时显示 `是`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 节点名称 | String | 是 | ≤ 64 字符，同一父节点下唯一 |
  | 子节点数 | Integer | 是 | 只读 |
  | 图纸数 | Integer | 是 | 只读 |
  | 可否删除 | Boolean | 是 | 只读，图纸数与子节点数均为 0 时为 是 |
- **来源**：新增设计

说明：参考产品只描述 PBS 层级创建，节点重命名、同级移动与删除语义未定义，本条规则为本规范新增。

## 图纸生命周期

### REQ-DRW-003 图纸新建与属性编辑

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望在 PBS 目录节点上新建图纸并编辑其属性，以便图纸元数据与归口保持一致。
- **验收标准**：
  1. 在选中的 PBS 目录节点上新建图纸，`文件名` 必填，为空提交返回 `REQUIRED_FIELD_MISSING`。
  2. `文件名` 在项目内唯一，重名新建返回 `409` 且图纸列表行数不变。
  3. 选中图纸后【编辑属性】修改 2 个属性值并保存，图纸列表该行显示保存后的 2 个值，且图纸内对象数不变。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 文件名 | String | 是 | 项目内唯一 |
  | 所属 PBS 节点 | String | 是 | — |
  | 图纸状态 | Enum(设计中/已校核/已批准/已发布) | 是 | — |
  | 版本号 | Integer | 是 | 只读 |
- **来源**：§6.2.2.1.2.1.1

### REQ-DRW-004 图纸导入与文件名唯一

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望把本地或平台文档中的图纸导入所选目录节点，以便复用已有图面成果。
- **验收标准**：
  1. 选中目录节点 →【操作】→【导入】，`来源` 下拉恰 `本地上传`、`选择平台文档` 2 项；选择 `选择平台文档` 时须依次指定 `工作区`、`文档管理器` 与文件。
  2. `文件` 扩展名仅支持 `SVG`、`DWG` 2 种；导入 1 个 SVG 后目标节点 `图纸数` 增加 1，导入结果作为新图纸出现在所选目录节点下。
  3. 导入与图纸管理器中已有图纸同名的 DWG 时返回 `409` 且图纸列表行数不变。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 来源 | Enum(本地上传/选择平台文档) | 是 | 恰 2 项 |
  | 工作区 | String | 条件必填 | 仅选择平台文档时 |
  | 文档管理器 | String | 条件必填 | 仅选择平台文档时 |
  | 文件 | List | 是 | 扩展名 ∈ {svg, dwg} |
- **来源**：§6.2.2.1.2.1.2

### REQ-DRW-005 图纸复制与位号冲突处理

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望复制整张图纸到新的路径并让副本位号进入查重流程，以便快速派生相似图纸且位号不重复。
- **验收标准**：
  1. 选中图纸 →【操作】→【复制】→ 弹窗内重选图纸路径 →【确定】完成复制；`副本文件名` 与源图纸不同，同名复制返回 `409`。
  2. 复制 1 张含 12 个带位号对象的图纸后，副本中 `位号` 显示为 `？` 的对象数为 12，`位号冲突数` 显示 12。
  3. 逐个修改 `位号` 至查重通过后位号显示正常值且唯一校验通过，副本 `位号冲突数` 变为 0。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 源图纸 | String | 是 | — |
  | 目标路径 | String | 是 | 重选图纸路径 |
  | 副本文件名 | String | 是 | 项目内唯一 |
  | 位号冲突数 | Integer | 是 | 只读 |
- **来源**：§6.2.2.1.2.1.4

### REQ-DRW-006 图纸移动与父节点变更

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望把图纸移动到结构树中的另一层级，以便调整图纸归口而不重建图纸。
- **验收标准**：
  1. 选中图纸 →【操作】→【移动】弹出结构树，所选目标层级作为该记录移动后的父级节点；移动后源节点 `图纸数` 减少 1、目标节点 `图纸数` 增加 1。
  2. 移动后图纸的 `所属 PBS 节点` 显示新父节点名称。
  3. 移动到自身当前父节点时返回 `NO_CHANGE` 且不产生新版本。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 图纸 | String | 是 | — |
  | 原父节点 | String | 是 | 只读 |
  | 新父节点 | String | 是 | — |
  | 移动时间 | DateTime | 是 | 只读 |
- **来源**：§6.2.2.1.2.1.5

### REQ-DRW-007 图纸权限设置

- **优先级**：必须
- **用户故事**：作为项目管理员，我希望按用户或角色对图纸授权，以便未授权人员只能只读查看图纸。
- **验收标准**：
  1. 图纸权限在图纸管理的【操作】中设置；`图纸权限` 表每行含 `主体`、`权限集` 2 列，`权限集` 至少覆盖 `查看`、`编辑`、`导出`、`删除` 4 项。
  2. 仅授予 `查看` 的用户打开图纸时工具栏的绘图命令 `禁用` 且保存返回 `403`。
  3. 未配置图纸权限时 `继承自` 显示 `PBS 节点` 并继承所属节点权限，节点权限为空时默认只读。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 主体 | String | 是 | 用户或角色 |
  | 主体类型 | Enum(用户/角色) | 是 | — |
  | 权限集 | List | 是 | ∈ {查看, 编辑, 导出, 删除} |
  | 继承自 | Enum(图纸/PBS 节点) | 是 | — |
- **来源**：§6.2.2.1.2.1.6

说明：参考产品手册该节仅一句「对图纸进行权限管理」，粒度未定义；本条只定义生命周期侧的入口与最低保证，角色与 PBS 节点 ACL 的三级授权链在 `docs/pid-platform/requirements/70-collaboration-and-permissions.md` 定义，本文档不重复。

### REQ-DRW-008 图纸预览与位号检索

- **来源**：§6.2.2.1.2.1.7

## 图纸版本与比对

### REQ-DRW-009 版本快照生成与数据回溯

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望对图纸手动保存节点快照并可回溯导出，以便保留关键时点的图面状态。
- **验收标准**：
  1. 图纸实时保存，退出时可直接关闭浏览器；单击左上角 `PIMCenter-保存` 对当前数据储存 1 个 `节点快照`。
  2. 连续执行 3 次 `PIMCenter-保存` 后数据回溯列表 `快照序号` 为 1、2、3；`快照序号` 单调递增且写入后不可修改，改写请求返回 `SNAPSHOT_IMMUTABLE`。
  3. 图纸管理器选中图纸 →【操作】→【数据回溯】可查看历史节点快照并支持导出；导出序号 2 的快照得到 1 个文件且内容与序号 2 一致。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 快照序号 | Integer | 是 | 单调递增，只读 |
  | 快照时间 | DateTime | 是 | 只读 |
  | 生成人 | String | 是 | 只读 |
  | 生成原因 | String | 否 | — |
  | 快照内容 | Binary | 是 | 只读 |
- **来源**：§6.2.2.1.2.1.8

说明：快照的命名规则、保留策略与可否删除参考产品未定义，本规范新增：快照序号单调递增、写入后不可修改、可按序号导出。

### REQ-DRW-010 任意两版本两两比对

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望勾选任意两个版本进行图面信息比对，以便看清两次修改之间的对象级差异。
- **验收标准**：
  1. 图纸管理器 →【操作】→【数据回溯】→ 勾选任意 2 个版本 →【比对】；恰勾选 2 个版本时【比对】可用，勾选 1 个或 3 个时按钮 `禁用`。
  2. 比对结果按 `新增`、`删除`、`修改` 3 组呈现，每组显示 `对象数` 与差异明细。
  3. 两版本完全一致时三组 `对象数` 均为 `0` 并显示「无差异」。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 版本 A | Integer | 是 | — |
  | 版本 B | Integer | 是 | ≠ 版本 A |
  | 差异类型 | Enum(新增/删除/修改) | 是 | 恰 3 组 |
  | 对象数 | Integer | 是 | 只读 |
  | 差异明细 | List | 是 | 只读 |
- **来源**：§6.2.2.1.2.1.9

说明：参考产品未定义比对维度，对象级 `新增`、`删除`、`修改` 三类差异与差异计数为本规范新增。

## 管线与管路层级

### REQ-DRW-011 新建管线与管路分支属性继承

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望新建管线后在其下连续绘制管路分支并自动继承线级属性，以便走线快速且属性一致。
- **验收标准**：
  1. 单击【新建管线】弹出管线新建对话框，输入数值后 `管线号` 按位号规则自动生成且不为空。
  2. 在已有管线节点下经元件库点「工艺管线」并在绘图区依次点击起点与终点绘制 1 条管路后，`管路节点` 自动生成且该管线 `管路数` 增加 1；管路的 `管道等级`、`公称直径`、`绝热等级`、`流体介质` 4 个线级属性初值继承自管线且允许用户修改。
  3. 支持连续点击绘制，连续点击 4 个点时 `流向箭头` 数量为 3 且方向与点击顺序一致。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 管线号 | String | 是 | 按位号规则自动生成 |
  | 管道等级 | String | 是 | — |
  | 公称直径 | String | 是 | — |
  | 绝热等级 | String | 否 | — |
  | 流体介质 | String | 是 | — |
  | 管路数 | Integer | 是 | 只读 |
- **来源**：§6.2.2.3.4.2.1.1

说明：手册 §6.2.2.3.4.2.1.1 正文记 `Ctrl+Y` 翻转流向、快捷键表记 `Shift+Y`，两处记载不一致，本规范统一取 `Shift+Y` 翻转 `流向箭头` 方向。

### REQ-DRW-012 管线管路管段三级关系与属性下传

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望管线、管路、管段三级对象的线级属性沿层级下传且允许管路级覆盖，以便统一改值与局部例外并存。
- **验收标准**：
  1. 三级关系为管线 → 管路 → 管段：1 条管线对 n 条管路，1 条管路对 n 个管段与管件；1 条管线含 2 条管路、每条管路含 3 个管段时层级树显示为 1 → 2 → 6 共 3 层。
  2. 线级属性先落到管线再下传给管路，管段继承所属管路当前值；修改管线 `公称直径` 后未打 `覆盖标记` 的 2 条管路与 6 个管段全部显示新值。
  3. 管路被手工改过的字段打上 `覆盖标记` 且 `属性来源` 显示 `覆盖`，后续管线改值不再覆盖该字段；某条管路手工改过 `公称直径` 后再改管线，该管路及其 3 个管段保持手工值，另一条管路仍同步。
  4. 管段无 `覆盖标记`，始终取所属管路当前值，`属性来源` 显示 `继承`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 所属管线 | String | 是 | 管路上 |
  | 管路号后缀 | String | 是 | 同一管线内自增 |
  | 所属管路 | String | 是 | 管段上 |
  | 覆盖标记 | Boolean | 是 | 仅管路 |
  | 属性来源 | Enum(继承/覆盖) | 是 | 只读 |
- **来源**：新增设计

### REQ-DRW-013 管路拆分合并与管路层级移动

- **优先级**：应该
- **用户故事**：作为工艺设计人员，我希望拆分合并管路分支并把管路拖到另一管线下，以便走线调整后层级与属性同步正确。
- **验收标准**：
  1. 【拆分合并】把首尾相连的 2 条管路合并为 1 条后该管线 `管路数` 减少 1；把 1 条管路拆成 2 条后 `管路数` 增加 1 且两条各自可独立赋属性。
  2. 左键点击目录树中的管路节点拖到目标管线节点释放后，源管线 `管路数` 减少 1、目标管线 `管路数` 增加 1。
  3. 移动后未打 `覆盖标记` 的线级属性显示目标管线的值，`跟随更新的属性数` 同步刷新。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 操作 | Enum(拆分/合并/移动) | 是 | — |
  | 源管路 | String | 是 | — |
  | 目标管路 | String | 条件必填 | 拆分与合并时 |
  | 目标管线 | String | 条件必填 | 移动时 |
  | 跟随更新的属性数 | Integer | 是 | 只读 |
- **来源**：§6.2.2.3.4.2.1.1

## 管件与阀门插入

### REQ-DRW-014 插入自动断开与移动自动补位

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望在管线上插入阀门时管线自动断开、拖动阀门时管线自动补位，以便管件在线编辑不打断走线连续性。

### REQ-DRW-030 用户环境随用户保存

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望显示与快捷键等使用习惯跟随用户存储，以便在不同图纸间保持个人操作环境一致。
- **验收标准**：
  1. 工具 →【用户环境】打开对话框，含 `显示`、`草图`、`快捷键` 3 张选项卡；`显示` 含 `配色方案`（明/暗）、`背景色`、`十字光标`、`栅格主线`、`追踪线`、`捕捉标记` 颜色与 `十字光标大小`，`草图` 与草图设置项一致。
  2. 用户环境跟随用户存储：用户 U 把 `配色方案` 设为 `暗` 后打开另一张图纸仍为 `暗`，用户 V 登录看到 `明`（默认）；`作用域` 字段读回为 `随用户`，值恒为该枚举。
  3. `快捷键组合` = 1–3 个修饰键（Ctrl/Shift/Alt）+ 恰 1 个主键；录入 `Ctrl+Q+W` 返回 `SHORTCUT_INVALID`，录入 `Ctrl+Ctrl+A` 归一化为 `Ctrl+A`。
  4. `Enter`、`Esc`、`Tab`、`Delete` 不能作为组合键内容，录入 `Enter` 返回 `SHORTCUT_RESERVED`；单独功能键仅允许 `F1`–`F12`；`空格`、`Ctrl+右键`、`IMAGEATTACH` 为固定键不可自定义。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 配色方案 | Enum(明/暗) | 是 | 默认 明 |
  | 背景色 | String | 是 | — |
  | 十字光标大小 | Number | 是 | — |
  | 快捷键组合 | String | 是 | 1–3 修饰键 + 恰 1 主键 |
  | 作用域 | Enum(随用户) | 是 | 只读 |
- **来源**：§6.2.2.3.3
