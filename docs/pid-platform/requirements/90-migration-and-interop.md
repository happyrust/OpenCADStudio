# 迁移与互操作需求

本文档定义存量数据迁移与外部系统互操作需求，共 7 条，按 6 个小节组织；需求编号规则见 `docs/pid-platform/requirements/00-overview.md`。自动化通道的现有操作面是 30 个读操作与 43 个执行操作（定义于 `src/mcp.rs`），本文档只定义对外契约的使用方式，不重新枚举操作。

## 存量图纸导入

参考产品手册的导入图纸入口是 §6.2.2.1.2.1.2，该节只记录入口位置与可接受的文件格式，不含识别语义、置信度分级与人工确认；本节补齐这部分缺口。

存量图纸识别按置信度分 3 级处置：

| 识别置信度等级 | 置信度区间 | 判定依据 | 处置 |
| --- | --- | --- | --- |
| 高置信 | ≥ 0.90 | 块字典或图层前缀命中且圈内位号配对唯一 | 自动接受 |
| 中置信 | 0.60–0.89 | 形状哈希命中但位号配对存在多解 | 进入人工确认队列 |
| 低置信 | < 0.60 | 仅几何相似或位号缺失 | 默认不导入，须人工逐个确认 |

进入人工确认队列的候选按以下 6 步完成人工确认：

1. 生成候选：识别引擎对每个未识别图元输出 1 条候选记录，含置信度与判定依据。
2. 逐条预览：确认界面按置信度分组列出候选，叠加显示原图元与拟指派类型。
3. 指派类型与位号：确认人选择目标类型并指派或校正位号。
4. 批量接受或驳回：按选择集一次提交，接受项转为正式 P&ID 对象。
5. 未确认项保留为未识别图元：不占位号、不计入材料清单。
6. 输出识别报告：含 `高置信`、`中置信`、`低置信` 各等级计数与未识别图元数。

### REQ-MIG-001 存量图纸识别的置信度分级

- **优先级**：必须
- **用户故事**：作为项目管理员，我希望存量图纸识别结果按置信度三级分流，以便高置信自动入库、低置信不污染数据。
- **验收标准**：
  1. 识别结果按置信度分为 `高置信`、`中置信`、`低置信` 3 级，区间分别为 `≥ 0.90`、`0.60–0.89`、`< 0.60`。
  2. `高置信` 记录自动接受；`中置信` 记录进入人工确认队列；`低置信` 记录默认不导入，须人工逐个确认后入库。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 置信度 | Number | 是 | 0–1 |
  | 识别路径 | Enum(块字典/图层前缀/形状哈希/几何相似) | 是 | — |
  | 判定依据 | String | 是 | 只读 |
  | 处置 | Enum(自动接受/人工确认队列/默认不导入) | 是 | 只读 |
- **来源**：新增设计

### REQ-MIG-002 人工确认流程与识别报告

- **优先级**：必须
- **用户故事**：作为项目管理员，我希望中低置信识别结果走固定人工确认流程并输出识别报告，以便迁移质量可核查。

  | 确认结果 | Enum(接受/驳回/未确认) | 是 | — |
  | 报告计数 | List | 是 | 含各等级与未识别数 |
- **来源**：新增设计

## 参考产品迁移

迁移对象恰为 5 类，来源载体与冲突处理如下：

| 迁移对象 | 来源载体 | 目标对象 | 冲突处理 |
| --- | --- | --- | --- |
| 类型库 | 配置包 ZIP（解包为 JSON 清单） | 类型树与属性模板 | 按类型编码更新，编码不存在则新建 |
| 符号库 | 配置包 ZIP（解包为 JSON 清单） | 符号定义与连接点 | 同名符号以目标环境版本优先 |
| 位号规则与颜色规则 | JSON | 规则集条目 | 同名规则以目标环境版本优先 |
| 项目主数据 | Excel（XLSX） | 项目主数据各类别 | 编码冲突时以目标环境为准并记录来源值 |
| 图纸 | DWG | 图纸与 P&ID 对象 | 位号冲突时保留目标位号并生成冲突条目 |

迁移执行幂等：以 `迁移批次号` + `来源主键` 去重，同一批次重跑不新增对象。

### REQ-MIG-003 参考产品迁移的字段映射与幂等重跑

- **优先级**：必须
- **用户故事**：作为实施工程师，我希望参考产品数据按五类对象映射迁入且可幂等重跑，以便迁移中断后安全续跑。
- **验收标准**：
  1. 迁移对象恰为 5 类：类型库、符号库、位号规则与颜色规则、项目主数据、图纸；各类的来源载体与冲突处理按本节表执行。
  2. 以 `迁移批次号` 与 `来源主键` 联合去重；同一批次重跑 1 次后新增对象数为 0，已存在对象按冲突处理列更新。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 迁移批次号 | String | 是 | 每批 1 个 |
  | 来源主键 | String | 是 | 去重键 |
  | 迁移对象 | Enum | 是 | 恰 5 类 |
  | 新增对象数 | Integer | 是 | 重跑时为 0 |
- **来源**：§5.1.13.2.2.2.2

## 三维模型关联

三维模型与 P&ID 对象的关联键恰为位号（Tag），一对一匹配；不按名称、不按坐标、不按图元句柄匹配。匹配结果分 3 类：

| 匹配结果 | 判定条件 | 处理 |
| --- | --- | --- |
| 完全匹配 | 三维模型位号与 P&ID 对象位号逐字相等 | 建立关联并写入关联表 |
| 归一后匹配 | 大小写与分隔符归一后位号相等 | 建立关联并在报告中标注归一差异 |
| 未匹配 | 归一后仍无对应位号 | 不建立关联，列入未匹配清单 |

### REQ-MIG-004 以位号为关联键的三维模型关联

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望三维模型与 P&ID 对象按位号一一关联，以便模型与图纸双向定位。
- **验收标准**：
  1. `关联键` 恰为 `位号` 1 项，一对 1 匹配；以名称、坐标或图元句柄提交的关联请求返回 `MATCH_KEY_INVALID`。
  2. 匹配结果恰为 `完全匹配`、`归一后匹配`、`未匹配` 3 类；`未匹配` 项列入未匹配清单并随报告输出。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 位号 | String | 是 | 关联键 |
  | 匹配结果 | Enum(完全匹配/归一后匹配/未匹配) | 是 | 恰 3 值 |
  | 归一规则 | String | 是 | 大小写与分隔符 |
  | 未匹配清单 | List | 是 | 只读 |
- **来源**：§3.2.1

## 自动化接口

对外自动化有三条通道：

| 通道 | 启动方式 | 协议 | 认证 |
| --- | --- | --- | --- |
| `--serve` | `OpenCADStudio --serve`（可加 `--port`） | stdio 行式 JSON，一行请求一行响应，状态跨请求保留 | stdio 模式继承启动进程身份；`--port` 模式每个请求携带 `token` |
| `--http` | `OpenCADStudio --http <port>` | REST，`GET /openapi` 提供 OpenAPI 3 描述 | `Authorization: Bearer <token>` |
| `--mcp` | `OpenCADStudio --mcp` | MCP 协议 over stdio，暴露 `ocs_sessions`、`ocs_read`、`ocs_execute`、`ocs_capture` 4 个工具 | 继承启动进程身份 |

操作面：MCP 通道提供 30 个读操作与 43 个执行操作；`--serve` 行协议的操作集合窄于 MCP，用于脚本与 CI；三通道共用同一套 handler，行为一致。批量执行单次上限 64 步。

### REQ-MIG-005 自动化接口三通道契约

- **优先级**：必须
- **用户故事**：作为集成开发者，我希望三条自动化通道契约明确且行为一致，以便脚本、REST 客户端与 MCP 客户端各取所需。
- **验收标准**：
  1. 三通道各通过 1 条端到端用例：`--serve` 行协议完成 1 次会话读取、`--http` 完成 1 次 REST 调用、`--mcp` 经 `ocs_execute` 提交 1 个执行操作。
  2. `--http` 请求缺失或携带无效 `token` 时返回 `401`；`--serve --port` 模式缺失 `token` 的请求同样返回 `401`。
  3. 批量执行单次上限 `64` 步，提交第 65 步返回 `BATCH_TOO_LARGE`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 通道 | Enum(--serve/--http/--mcp) | 是 | 恰 3 值 |
  | 会话 ID | String | 是 | ocs_session_id |
  | token | String | 条件必填 | --http 与 --serve --port 必填 |
  | 批量步数 | Integer | 是 | ≤ 64 |
- **来源**：新增设计

## 插件扩展

插件是带外进程：宿主以 `--ocs_plugin_runner <socket> <cdylib>` 拉起隔离子进程并 `dlopen` 插件，经本地 socket IPC 通讯。清单文件 `plugin.toml` 声明 `id`、`api_version`（当前 `13`）、`rustc_version`、`command_prefixes`、`xdata_apps`。插件的域数据必须存实体的 XDATA 以保证 DWG 往返不丢；Web 构建不加载插件。

### REQ-MIG-006 插件扩展点与 XDATA 持久化

- **优先级**：必须
- **用户故事**：作为插件开发者，我希望扩展点经清单声明且域数据经 XDATA 持久化，以便插件能力随 DWG 往返保留。
- **验收标准**：
  1. `plugin.toml` 的 `api_version` 与宿主支持区间不匹配时加载被拒绝，返回 `PLUGIN_API_VERSION_MISMATCH` 并在日志记录期望值与实际值各 1 个。
  2. 插件写入的域数据经 `XDATA` 挂在实体上；DWG 保存、关闭、重新打开后读取值与原值逐字一致。
  3. Web 构建不加载插件，`--ocs_plugin_runner` 在该构建中被忽略且启动日志出现 1 条说明。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | id | String | 是 | 插件唯一标识 |
  | api_version | Integer | 是 | 当前 13 |
  | rustc_version | String | 是 | 编译期注入 |
  | command_prefixes | List | 是 | 注册命令前缀 |
  | xdata_apps | List | 是 | XDATA 应用名 |
- **来源**：新增设计

## 数据交换标准

三套外部标准本期的范围声明：

| 标准 | 是否在范围内 | 理由 | 后续阶段位置 |
| --- | --- | --- | --- |
| DEXPI | 范围外 | 需要 P&ID 语义类树与标准类库的双向映射，工作量与 ISO 15926 同量级 | P4 之后的扩展阶段，路线图尚未排期 |
| ISO 15926 | 范围外 | 需要本体映射与 Part 4 参考数据校验，超出本期规格范围 | P4 迁移与互操作 |
| CFIHOS | 范围外 | 需要业主交付规范与 RDL 版本对齐，取决于客户项目而非产品 | P4 迁移与互操作 |

本期只定义交换的接口形状：文件级导入导出与三条自动化通道；不定义上述三套标准的数据模型映射。任何对外声明都不得把这三套标准描述为已支持。

### REQ-MIG-007 数据交换标准的范围声明

- **优先级**：必须
- **用户故事**：作为产品经理，我希望三套数据交换标准的范围外声明成文且理由各自具体，以便对外口径一致。
- **验收标准**：
  1. `DEXPI`、`ISO 15926`、`CFIHOS` 3 行的 `是否在范围内` 均为 `范围外`，各行理由互不相同且 `后续阶段位置` 非空。
  2. 对外能力声明中出现上述任一标准名并描述为已支持时，该声明被拒绝并返回 `CLAIM_OUT_OF_SCOPE`；本期交付物不含三套标准的数据模型映射。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 标准名 | Enum(DEXPI/ISO 15926/CFIHOS) | 是 | 恰 3 值 |
  | 是否在范围内 | Enum(范围内/范围外) | 是 | 本期恒为范围外 |
  | 理由 | String | 是 | 非空且各行不同 |
  | 后续阶段位置 | String | 是 | 非空 |
- **来源**：新增设计
