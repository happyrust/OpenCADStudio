# 系统架构

## 分层架构

本平台按五层组织，依赖方向自上而下，下层不感知上层语义。层间边界同时是脱机边界与替换边界：任一层的实现可在契约不变的前提下替换，桌面端在服务端缺席时可沿层边界截断并独立运行。五层各承担一项可判定的正确性责任：L1 可被其他图种复用，L2 决定 P&ID 语义正确性，L3 决定多用户一致性，L4 决定交付物质量，L5 决定治理范围。

### L1 绘图内核

**职责** 负责实体模型（夹点、分解、属性行、绘制顺序）、块与动态块、图层与图层状态、外部参照、文字与标注渲染、捕捉栅格、DWG/DXF 多版本读写、图纸空间与视口、出图通道。本层不感知任何 P&ID 概念，全部行为对业务语义中立。

**上游消费者** L2 P&ID 语义是本层业务读写的主要消费者，所有 P&ID 对象的写入与读取都经 L2 翻译为实体与块操作。L4 校验交付的出图与统一导出直接调用本层的出图原语，这是本层唯一的直接只读消费者。

**向下依赖** 无，本层自立，不向下依赖任何业务层。已有复用锚点为 `src/entities/`（实体与块底座）、`src/io/mod.rs`（DWG/DXF 读写）与 `src/io/plot_emit.rs`（出图通道），三者构成其他图种复用本层时的全部入口。

### L2 P&ID 语义

**职责** 负责类型库与属性模板、图例标准与符号库、符号实例化、连接点与拓扑边、位号生成与唯一校验、颜色规则求值、管路与管段划分、页间连接符、相交断线、项目主数据引用。本层新增能力为类型库、属性模板、图例库可视化编辑与页间连接符语义四项。

**上游消费者** L3 数据服务、L4 校验交付与编辑器三方直接消费本层：L3 读取类型与属性定义用于持久化，L4 读取规则定义与类型解析用于检查，编辑器经命令面写入符号实例与位号。

**向下依赖** 本层只向下依赖 L1 绘图内核，即实体、块、图层、XDATA 持久化与出图五类能力。已有复用锚点为 `src/io/pid_legend/`、`src/app/commands/pidlegend.rs`、`assets/pid-legend.json`、`src/io/pid_view_filter.rs`、`src/io/pid_legend/xdata.rs`。

### L3 数据服务

**职责** 负责位号主数据、带类型属性持久化、跨图纸拓扑图、图纸版本快照与比对、同步与冲突检测、审计落库。本层新增服务端项目库与跨图纸拓扑持久化两项能力，是脱机数据升格为项目权威数据的唯一入口。

**上游消费者** L4 校验交付、编辑器与 L5 平台三方消费本层：L4 拉取全项目对象与拓扑执行检查，编辑器读写属性与位号主数据，L5 平台只读取审计与权限判定所需的事实。

**向下依赖** 本层向下依赖 L2 P&ID 语义的类型与属性定义，以及 L1 绘图内核的图纸文件快照读写。已有复用锚点为 `src/io/pid_pipes.rs`（拓扑建图输入）与 `src/app/automation.rs`（records / record_schema / set_properties / xdata_set 四条命令）。

### L4 校验交付

**职责** 负责设计规则检查引擎（DSL 解析、触发时机、结果模型）、材料清单聚合、报表模板、发布包组装、数据发布与导出矩阵、图纸输出。本层新增规则引擎与材料清单语义两项能力，是交付物质量的最后关口。

**上游消费者** L5 平台消费本层的发布签核与审计结果，外部消费者经发布包与自动化通道消费本层产物。编辑器不直接调用本层，只在保存与发布两个触发点接收本层返回的检查结果。

**向下依赖** 本层向下依赖 L3 数据服务的全项目对象与拓扑、L2 P&ID 语义的规则定义与类型解析、L1 绘图内核的出图能力。已有复用锚点为 `src/io/pid_legend/export.rs`、`src/mcp.rs` 与 `src/io/plot_emit.rs`。

### L5 平台

**职责** 负责用户与角色、项目空间、PBS 节点权限、图纸状态、协作锁定、审计日志。本层收敛为最小可用，不提供通用低代码能力，全部治理能力围绕 P&ID 交付闭环组织，不向外扩张。

**上游消费者** 全部层与全部客户端都是本层消费者，权限判定、审计写入与协作锁定属于横切关注点：任何会话在读写图纸前必须先经本层三级判定链求值，任一判定不通过即降级为只读。

**向下依赖** 无，本层为横切层，只向 L2–L4 提供判定结果，不读取其内部结构。需要说明：`src/io/edit_lock.rs` 只是文件占用锁，不构成权限模型，不视为本层的既有实现。

## 跨层交互契约

层间调用一律沿依赖方向向下发起，已定义的交互契约共九条，如下表所示。

| 调用方 | 被调用方 | 交互内容 | 契约载体 | 失败与降级 |
| --- | --- | --- | --- | --- |
| L2 P&ID 语义 | L1 绘图内核 | 符号实例以块引用写入、归属图层、几何编辑 | 实体加 XDATA 键 `PID_SEMANTICS` | 块缺失时降级为几何图元并计入未解析例外 |
| L2 P&ID 语义 | L1 绘图内核 | DWG/DXF 原子保存与重开校验 | `save_verified` | 校验和不匹配时保留 `.bak` 并中止保存 |
| L3 数据服务 | L2 P&ID 语义 | 读取类型定义与属性模板 | 类型库查表（TypeId 到属性清单） | 类型缺失时对象标记为未分类并禁止发布 |
| 编辑器 | L2 P&ID 语义 | 插入符号、生成位号、写属性 | 绘图命令加事务 | 位号冲突显示「？」并阻断保存 |
| L4 校验交付 | L3 数据服务 | 拉取全项目对象与拓扑执行规则检查 | 批量快照查询，每批 ≤ 2000 个对象 | 服务端不可达时退化为单图检查并在结果中标注为降级 |
| L4 校验交付 | L2 P&ID 语义 | 解析类型对应的位号规则与颜色规则 | 规则解析结果 | 规则未定义时跳过该检查项并记提示 |
| L4 校验交付 | L1 绘图内核 | 出图与统一导出 | 绘图器加统一导出 schema | 出图失败不阻断数据导出 |
| L5 平台 | L2–L4 | 权限三级判定（菜单、PBS 节点、图纸状态）与审计写入 | 判定服务接口 | 判定服务不可用时降级为只读 |
| 外部客户端 | L4 校验交付 | 自动化查询与发布 | `src/mcp.rs` 的 30 个读操作与 43 个执行操作 | 未授权操作返回 403 |

任何跨层调用只能向下依赖一层；确需跨越一层以上时，调用必须经中间层代理转达，不得跳过中间层直连。唯一例外是 L4 校验交付可只读调用 L1 绘图内核的出图与导出原语：该调用不授予写权限，不得经此修改图纸数据、图层状态或编辑锁。层间不得共享内存对象，各层只通过上表所列契约载体交换数据，契约载体之外的私有结构对邻层不可见。

## 脱机与在线运行模式

**L2 可在无 L3 时独立工作**，即本地脱机模式。两种运行模式的权威源与能力边界如下表所示。

| 运行模式 | 数据权威源 | 可用能力 | 不可用能力 |
| --- | --- | --- | --- |
| 本地脱机模式 | 图内 XDATA 与随图 sidecar 文件 | 绘图、符号插入、位号生成与唯一校验、属性编辑、单图规则检查、出图 | 跨图纸拓扑、位号主数据全局唯一性、图纸版本快照比对、协作锁定 |
| 接入服务端模式 | 服务端项目库 | 上述全部能力以及跨图纸拓扑持久化、全局位号唯一性、多角色协作、审计 | 无 |

脱机到在线的切换由同步步骤完成。同步以位号为粒度比对图内 XDATA 与服务端主数据，冲突同样以位号为粒度报告；冲突未解决前，该位号在服务端保持只读，其余位号的读写不受影响。
